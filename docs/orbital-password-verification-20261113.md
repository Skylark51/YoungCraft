# 포터블 오비탈 / 비밀번호 인증 검증 (2026-11-13)

실행 대상: C드라이브 별도 설치본 `Youngcraft Portable/Youngcraft.exe`. 실제 FCHK(66개 원자)를 열고 라이온 서버에 사용자가 앱의 마스킹된 창에서 비밀번호를 직접 입력했다. Alpha HOMO 125, LUMO 126을 해상도 80에서 각각 최초 생성한 뒤, 표를 한 번씩 클릭해 6회 교대로 표시했다.

| 관측 항목 | 결과 |
| --- | --- |
| cube 메모리 캐시 사용 | 6회 |
| 등가면 캐시 사용 | 6회 |
| 교대 선택 중 새로운 Gaussian 생성 | 0회 |
| 교대 선택 중 등가면 재생성 | 0회 |
| 표시 처리 시간 | 5.0914, 2.6051, 3.3539, 2.5023, 3.9616, 2.5888 ms |
| 평균 / 최대 | 3.35 / 5.10 ms |
| 교대 선택 구간의 UI 이벤트 지연 100ms 초과 | 0회 |
| 모니터 작업 영역 | 2048 × 816 (Qt 논리 좌표) |
| 기본 관리창 프레임 | (1351, 10), 680 × 764; 작업 영역 내 포함 |

표시 시간은 메모리 cube 선택부터 등가면 캐시 복원·GPU 업로드·스타일 반영까지의 UI 처리 시간이다. 디스플레이 스캔아웃까지의 종단 지연 측정은 아니다. 최초 FCHK 열기/초기 생성과 접근성 도구의 전체 표 조회에서는 별도 UI 지연이 있었으며 위 교대 선택 구간에 포함하지 않았다. 모니터를 바꾸거나 창을 다시 열면 현재 화면의 작업 영역으로 다시 배치한다. 420 × 480 축소 창의 스크롤/테마/경계는 GUI 회귀 검사로 확인했다.

인증은 `SSH_ASKPASS_REQUIRE=force`로 앱의 비밀번호 창에 연결한다. Windows OpenSSH가 한글·공백이 있는 절대 보조 프로그램 경로를 실행하지 못하는 회귀를 확인해, SSH의 작업 디렉터리를 포터블 폴더로 지정하고 상대 보조 프로그램 경로를 사용한다. 보조 프로그램은 임의 토큰으로 보호한 사용자 전용 로컬 IPC를 통해 비밀번호를 받는다. 비밀번호를 프로세스 인자, 환경 변수, 설정 파일, 진단 기록에 넣지 않는다. 메모리 캐시는 현재 앱 세션에서만 유지한다. 호스트 키 검증은 계속 사용한다.

로컬 가짜 암호화 키를 실제 Windows `ssh-keygen`과 인증 보조 프로그램으로 복호화하는 검사를 한글·공백 경로에서 통과했다. 이 검사는 실제 계정이나 사용자 키를 사용하지 않는다. 관련 테스트는 오비탈/IPC 12개 통과(외부 fixture 2개 제외), GUI 8개 통과, 선택 CTest 7개 통과다.

진단은 `YOUNGCRAFT_ORBITAL_DIAGNOSTICS`가 지정된 QA 실행에서만 기록한다. 일반 바로가기 실행에서는 기록하지 않는다. 원본 관측 파일은 로컬 `.build/ssh-password/real-portable-final.jsonl`, 요약은 `alternation-summary.json`에 보관하며 버전 관리에 포함하지 않는다.

OpenSSH 동작 참고: [공식 Windows readpass 구현](https://github.com/PowerShell/openssh-portable/blob/latestw_all/readpass.c).

배치 점검에서 이미 열린 창을 다시 호출하면 제목 표시줄이 위로 밀리는 문제를 발견했다. 프레임 좌표를 사용하는 move()로 보정하고, 반복 호출 4회·420×480 크기 유지·화면 밖에서 복구하는 회귀 검사를 추가해 통과했다.
