# 오비탈 창 배치·테마 및 CI 수정 (2026-11-14)

## CI 원인과 수정

이전 PR #18의 파서 검사는 성공했다. main 병합 후 [포터블 배포 실행 43563102253](https://github.com/Skylark51/YoungCraft/actions/runs/43563102253)은 Visual Studio Release 링크에서 `youngcraft_app.dir/Release/qrc_youngcraft.obj`를 찾지 못해 실패했다. Qt AUTORCC 출력을 OBJECT library에서 실행 파일로 전달하던 구성을 제거하고, 리소스를 Youngcraft와 test_smoke 실행 파일에 직접 컴파일하도록 변경했다. 별도의 깨끗한 Visual Studio 17 2022 빌드에서 앱·파서·모델·편집기를 빌드하고 CI와 같은 CTest 세 가지를 모두 통과했다.

## 화면 변경

- 앱 팔레트의 종이색을 분자 뷰의 배경에도 적용한다. 기존 검정 배경 설정으로 시작해도 선택된 앱 테마와 맞춘다. 표시 스타일 편집과 명시적 프리셋 선택은 계속 사용할 수 있다.
- 오비탈 관리 창은 기본 1120×680 이내의 가로형 창으로 연다. 실제 크기는 현재 모니터 작업 영역에 맞춰 제한하며 장식 프레임도 포함해 위치를 보정한다.
- 왼쪽은 파일·서버·MO 및 분석 목록, 오른쪽은 생성·격자·표면·색상 설정이다. 분할선을 이동할 수 있고 각 영역은 독립적으로 세로 스크롤한다. 폭이 780px 미만이면 작은 화면을 위한 세로 배치로 전환한다.
- 오비탈 관리·서버 설정·확대 분석 표는 불투명 창으로 표시한다. 배경 문양이 표와 설정 뒤에 겹쳐 보이지 않도록 단색 작업 영역을 사용한다.
- 앱 소유 대화상자를 열 때 현재 화면 작업 영역 안으로 크기와 위치를 보정한다. 음수 좌표의 보조 모니터도 고려하며 기존 최대화 상태는 유지한다.

## 검증 방법

좌우 영역의 실제 너비, 1120×640 / 840×560 / 420×480 크기의 배치 전환, 가로 넘침, 장식 프레임의 화면 내 포함, 반복 열기와 화면 밖 위치 복구, 관련 대화상자의 위치 복구, 불투명 속성, 테마 변경 및 파일 열기 후 배경, OpenGL framebuffer의 실제 배경 픽셀을 검증한다. 오비탈 캐시·표면 표현·MEP와 선택 수소 편집의 회귀 검사도 포함한다.

초기 로컬 증분 빌드에는 오래된 렌더링 객체 파일이 섞여 설정값과 화면 출력이 달랐다. 별도 Visual Studio 빌드로 원인을 분리한 후 Ninja도 전체 clean build하여 배포한다. GPU 렌더러 알고리즘을 변경하는 우회는 적용하지 않았다.

## 로컬 결과

Ninja 전체 clean build 후 파서(ORCA/Gaussian), 오비탈, 모델, 편집기 CTest 5개 모두 성공했다. 실제 Windows OpenGL GUI 시나리오 8개도 모두 성공했다(init/cleanup 포함 10 passed). 분자가 있는 framebuffer의 배경 픽셀까지 앱 팔레트와 동일함을 확인했다. 별도 Visual Studio 빌드의 앱 링크 및 CI와 동일한 CTest 3개도 성공했다.
